# 0004 — Correct rounding is the accuracy target, gated exactly against a correctly rounded rows

**Status**: Accepted
**Date**: 2026-11-11

## Context

pravash calls nine of Rust's std transcendentals: `exp`, `ln`, `log10`, `powf`, `sin`, `cos`, `sin_cos`, `atan2`
and `hypot`. It also calls `cbrt`. Rust 1.3.0 takes them from glibc 2.44, except cbrt, where rustc
links compiler_builtins' (`port-parity.md` §3). Neither glibc nor the Cyrius counterparts available at M0 are
correctly rounded:
- **The Cyrius counterparts.** On the golden sweep (`tests/golden/math.tsv`, 33,239 rows), M0 measured each
  counterpart against glibc (`port-parity.md` §2.2). The exp polyfill, the ln polyfill, the sin/cos builtins,
  ganita's atan2, hypot and pow are each 1 ulp from glibc on 2–25 % of rows, and ganita's hypot is 2 ulp on two.
  There is no `log10` at all, and `ln / LN10` is 1–2 ulp off.
- **glibc.** Measured against MPFR on the same rows, glibc 2.44 itself misrounds 43:
  - 21 of the 801 log10 rows;
  - 11 of the 1,715 hypot rows;
  - 3 sin results (in `sin` and `sin_cos`), 2 atan2, 1 exp, 1 ln and 1 powf.

Two implementations each about 1 ulp from the true value can differ by 2, so M0 set K = 2 for these functions
and kept powf measured (§2.2). That bound hides a real 1-ulp error on either side. pravash's solvers feed these
results through thousands of steps (Tait's `powf`, Lamb–Oseen's `exp`, the DST's `cos`, MPM's `atan2` and `hypot`),
where the port-parity rule multiplies one ulp by each row's sensitivity S.

The ecosystem has answered this twice:
- **kimiya's ADR 0006:** correct rounding is the accuracy target, compared against a correctly rounded rows;
- **impetus's ADR 0011, with its hypot, pow and atan2 amendments:** the same for exp, sin, cos, hypot, pow and
  atan2, with a three-phase implementation (`src/crmath.cyr`).

The user set the policy: accuracy across the libraries, not parity with glibc ("WE WANT TO BE BETTER THAN glibc",
kimiya; carried into this port as CLAUDE.md's "accuracy beats glibc"). pravash's decision D2 (port plan §0) chose
how to get there: vendor the two existing copies now, and convert to ganita's tier when it ships (ledger L1).

## Decision

1. **Every std transcendental is correctly rounded**: round-to-nearest-even of the exact value on every double
   argument, using + − × ÷, the f64 rounding builtins and integer operations only. The bits are therefore the same
   on every target. The implementations are vendored, each marked `UPSTREAM(L1)`, and converted when ganita's
   correctly rounded tier ships:
   - **exp, sin, cos, sin_cos, hypot, pow and atan2:** `src/crmath.cyr`, impetus's crmath (its ADR 0011 and
     amendments) with the `_pv_cr_` prefix. Its tables are `src/crmath_data.cyr`, generated by
     `scripts/golden/crtables.py` from π and ln 2 computed exactly in integers.
   - **ln and log10:** `src/crlog.cyr`, kimiya's (its ADR 0006), on crmath's TwoSum and TwoProduct. It uses a fast
     path with a proven error bound and a rounding test, else a triple-double accurate path to 2^-135. Its tables
     are `src/crlog_data.cyr`, generated by `scripts/golden/lntables.py` from MPFR. The generator asserts the
     properties the error analysis relies on.
   - **cbrt:** ganita's `ganita_f64_cbrt`, which already is correctly rounded. It equals 1.3.0's
     compiler_builtins cbrt on all 1,025 rows.

   The solvers call these only through `src/mathx.cyr`'s wrappers (`_pv_exp`, `_pv_ln`, `_pv_log10`, `_pv_powf`,
   `_pv_sin`, `_pv_cos`, `_pv_sin_cos`, `_pv_hypot`, `_pv_atan2` and `_pv_cbrt`). Converting L1 therefore changes
   the wrappers' bodies and nothing else.
2. **The reference is the correctly rounded rows**, as kimiya's ADR 0006 and impetus's ADR 0011.
   - **Rows.** `tests/golden/<module>.cr.tsv` holds every golden row whose outputs change when each exp, ln,
     log10, sin, cos, hypot, pow and atan2 result in 1.3.0's operations is correctly rounded (MPFR 4.2.2
     through ctypes, `scripts/golden/mpfr_ref.py`). The key is the row's fn and inputs, byte for byte.
   - **Notes.** Each row's note gives 1.3.0's own outputs and every call glibc misrounded.
   - **Generation.** `validate.py --write` writes the file, and a plain run checks it is current.
   - **The harness.** It compares a corrected row against the corrected outputs and reports a pass as
     *accepted (ADR 4)*. Matching 1.3.0's misrounded outputs instead is a failure: kimiya's transitional
     rule is off.
3. **K = 0 for every one of these functions**, against the correctly rounded rows, powf included. With one side exact,
   any distance is a defect in the port. Later milestones extend the correctly rounded rows to their modules' rows.
   Where a row's operations go through these primitives, its corrected outputs are 1.3.0's operations
   recomputed with correctly rounded calls (impetus's method: a Python transcription checked bit for bit against
   Rust 1.3.0 on the glibc side).

## Consequences

- **Positive.**
  - The port's transcendentals are more accurate than 1.3.0's on 43 math rows and never less accurate.
  - Every class C math row is gated at 0 ulp: 33,239 rows, identical on x86_64 ELF, x86_64 PE and aarch64.
  - There is no tolerance to widen, so a regression in any primitive fails its rows outright. The mutation checks
    (`port-parity.md` §6) show it: a 1-ulp polyfill exp fails 164 rows, and a one-bit table edit fails rows and
    `validate.py`.
  - The solvers' sensitivity S no longer multiplies a primitive's error: there is none to multiply.
- **Negative.**
  - **Speed.** Against the counterparts they replaced, the correctly rounded functions cost:
    - 0.9× (ln, which is faster) to 5.2× (hypot);
    - 22× for atan2, whose mean (1.4 µs) is dominated by a rare slow path that runs on 0.4 % of arguments.

    Against glibc they cost 11–103× (`docs/benchmarks-rust-v-cyrius.md`). Speed is measured, not gated. These rows
    are findings for ganita's tier (the L1 request carries them) and for the compiler.
  - **What pravash now owns.** 2,512 lines of vendored code and 1,171 lines of generated tables until L1 converts.
    MPFR (libmpfr.so.6) is a local dependency of `validate.py`; neither the library nor CI needs it.
  - **Thread safety.** crmath loads its tables lazily behind a plain flag, and keeps slow-path counters in
    globals. `src/par.cyr` (M3) therefore calls `_pv_cr_load()` before it starts workers: on aarch64 a worker must
    never see the flag before the tables. The counters are racy but never feed a result.
- **Neutral.**
  - **Keeping the copies in step.** `crtables.py`, `mpfr_ref.py` and the two `.cyr` files are copies, so
    upstream fixes have to be carried over. Their headers name their sources.
  - **The tier's third consumer.** The ganita request now has pravash's ln and log10 and its measurements.

## Alternatives considered

- **Keep K = 2 against glibc.** Rejected. It accepts a 1-ulp error on either side, can't gate powf (ganita's open
  `pow(-1, huge)` defect), and has no log10 counterpart at all. It is also the "parity with glibc" target the
  policy rejects.
- **Wait for ganita's tier.** Rejected by CLAUDE.md ("upstream requests never block") and ADR 0003: the port
  ships a marked stand-in and converts later.
- **Vendor only one source.** Considered.
  - **impetus's alone** has no ln or log10. Its `log_dd` serves pow and is not a correctly rounded ln entry
    point.
  - **kimiya's alone** has exp, ln, log10, sin, cos, atan2 and pow but no hypot. It would also mean a second
    exp/sin/cos family beside the one the ganita request is seeded from.

  Taking ln and log10 from kimiya and the rest from impetus keeps one implementation per function. Both are
  verified against MPFR in their home repos.
- **Match glibc bit for bit** (transcribe glibc's algorithms). Rejected: glibc misrounds, its results depend on
  its build (FMA or not), and copying its last-ulp errors is what CLAUDE.md forbids.
